# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`corpus_aecbot` is a **generated data corpus**, not an application. It holds the scraped/extracted
source material (WordPress pages + PDF booklets from `melenchon2027.fr`, the "Avenir en Commun" /
AECBot program) and the derived knowledge-base files built from it for import into a Custom GPT.
There is no app code, test suite, or build step inside this directory — everything here is either
raw collected data or output regenerated by scripts that live one level up, in the parent directory
(`aecbot/` — not a git repo).

Treat files in this directory as **data, not code**: never hand-edit a generated file (`markdown/*`,
`pdf_markdown/*`, `index.csv`, `inventaire_complet.json`, `pdf_manifest.json`,
`extraction_manifest.json`, `gpt_manifest.json`, `gpt/AEC_*.md`, `GPT_programme_*.md`). Re-run the
producing script instead, so the manifests stay consistent with the files they describe.

## Pipeline and commands

The pipeline is four independent Python scripts, run in order, all living in the parent directory
and all assuming the current working directory is the parent (`aecbot/`), with `corpus_aecbot/` as
their fixed output root (`Path('corpus_aecbot')` / `ROOT = Path("corpus_aecbot")`):

```bash
cd ..   # scripts expect to run from aecbot/, with corpus_aecbot/ as a relative subpath
python3 -m pip install -r requirements.txt   # requests, beautifulsoup4, markdownify (fitz/PyMuPDF needed too, not pinned)

python3 collecte_wp.py      # 1. scrape WP pages+posts under /programme/ -> markdown/, index.csv,
                             #    inventaire_complet.json, GPT_programme_0X.md
python3 download_pdfs.py    # 2. download every PDF media attachment -> pdfs/, pdf_manifest.json
python3 extract_pdf.py      # 3. extract PDF text per page (PyMuPDF) -> pdf_markdown/, extraction_manifest.json
python3 build_corpus.py     # 4. classify + dedupe + chunk extracted docs -> gpt/AEC_*.md, gpt_manifest.json
```

`fix_programme.py` and `test_column.py` are one-off repair/debug utilities for a single known-bad
PDF (title containing "PROGRAMME SITE 2025", e.g. `15699_A5-PROGRAMME-SITE.pdf`) whose text extracts
better as two side-by-side columns than as a single flow; `fix_programme.py` backs up the original
extraction to `*.original.md` before overwriting it. Run these only for that specific document, after
`extract_pdf.py`, before `build_corpus.py`.

`build_corpus.py` useful flags:
- `--root corpus_aecbot` (default)
- `--max-kib 450` — max size per generated knowledge file (splits large PDFs at `## Page N` boundaries)
- `--include-archives` — include the NFP 2024 contract (excluded by default; it's a *different*
  program, not an AEC edition)
- `--include-other` — include press kits / unclassified docs (excluded by default)

There is no lint/test command — correctness here means re-running the pipeline and checking the
manifests (counts of included/excluded/error/duplicate) described below.

## Pipeline architecture (why the files are organized this way)

Four stages, each stamping metadata forward into the next stage's manifest, keyed by the WordPress
media/post `id`:

1. **`collecte_wp.py`** calls the WP REST API (`/wp-json/wp/v2/pages`, `/posts`), keeps only items
   whose URL starts with `/programme/` and whose rendered text is >100 chars, converts HTML→Markdown,
   and writes one file per doc to `markdown/`. Also repackages everything kept into
   `GPT_programme_01.md`/`02.md` (≤300k chars/file) for *direct* Custom GPT import — this is a
   separate, simpler artifact from the `gpt/AEC_*.md` files produced later in step 4.
2. **`download_pdfs.py`** pulls every `application/pdf` media item from `/wp-json/wp/v2/media`,
   prefixes each filename with its WP id to avoid collisions, and records `pdf_manifest.json`.
3. **`extract_pdf.py`** runs PyMuPDF (`fitz`) over every PDF in `pdf_manifest.json`, emitting one
   `pdf_markdown/<stem>.md` with explicit `## Page N` headers per page, and appends extraction
   status (`ok`/`empty`/`error`) to `extraction_manifest.json`.
4. **`build_corpus.py`** reads `extraction_manifest.json`, classifies each document by filename/URL
   heuristics into one of six categories, drops exact duplicates (SHA-256 of whitespace-normalized
   body) and documents excluded by default (`archive`, `other`), then packs the rest into size-capped
   `gpt/AEC_<category>_NN.md` files (splitting only at `## Page N` boundaries so a page is never cut
   mid-text), and writes `gpt_manifest.json` with full provenance per document (`included`, `reason`
   if excluded, which knowledge file(s)/part it landed in).

### Document categories (`build_corpus.py: CATEGORY`/`classify`)

Classification is filename/URL-based and intentionally documentary, not semantic:
- `programme` → the general program PDF (`A5-PROGRAMME-SITE`, `programme-abrege`)
- `livret` → thematic booklets (`Livret_UP_*`, `ASS-LIVRET-*`)
- `plan` → thematic/investment plans (`Plan_UP_*`, `PLAN-EUROPE_*`)
- `recent` → anything under a `/2026/` upload path
- `archive` → the 2024 NFP ("Front Populaire") contract — a different coalition's program, **excluded
  by default**
- `other` → press kits, open letters, anything unclassified — **excluded by default**

`gpt/AEC_00_LIRE_AVANT_IMPORT.md` (regenerated by `build_corpus.py`, don't hand-edit) is the
documentary ground rules for anyone (human or model) consuming the `gpt/AEC_*.md` files — it is the
most important single file to read before answering questions from this corpus:
- The general program is a **provisional** reference; check for a newer edition before citing it.
- Always distinguish programme général / livrets / plans / 2026 publications / archives.
- The `modified` date is a WordPress edit timestamp — **not** evidence of drafting or adoption date.
- Always cite title + source URL + PDF page marker (`## Page N`).
- Never invent a measure or quote; flag contradictions between editions.
- NFP archives and press kits/unclassified docs are excluded unless the corresponding `--include-*`
  flag was used.
- Filename-based classification is indicative only — check `gpt_manifest.json` before relying on it.

## Known caveats (carried over from the scripts' own comments)

- The WP API scrape doesn't guarantee full booklet/measure coverage and can miss JS-rendered content
  — always sanity-check `index.csv` rather than assuming completeness.
- `15699_A5-PROGRAMME-SITE.md` has a `.original.md` backup sitting next to it from the column-fix
  re-extraction; the non-`.original` version is the one actually referenced by the manifests.
- `gpt_manifest.json` is the authoritative provenance record — it says, per source document, whether
  it was included, why it was excluded if not, and exactly which `gpt/AEC_*.md` file/part contains it.
